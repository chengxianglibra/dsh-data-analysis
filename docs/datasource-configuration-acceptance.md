# 数据源配置请求与编辑验收

## 结果与责任边界

本地实现支持 `marivo_datasource_configure` 发起新增/选择或编辑请求，在所属 Session 的右侧 Tab
完成保存和连接测试后，返回原工具调用。数据源管理页也可独立编辑；名称和引擎固定。
Harness 拥有 Session、工具和凭证，Marivo 拥有配置及连接测试，插件只连接请求、页面和验证结果。
契约见[数据源与凭证](modules/datasource-credentials.md)和[架构](architecture.md)。

Web 验收证明：

- 新请求自动打开所属 Session 的新增表单；关闭 Tab 后仍可从待办重新打开原请求。
- 切换 Session 不把表单带到其他会话；连接重置后点击“待配置”可重新打开，失效旧 Tab 不被继续使用。
- 新增后进行真实连接测试并返回原调用；失败时保留已保存配置，编辑修复后重新测试并续接。
- 编辑表单的名称和引擎只读；完成请求后可返回管理页，独立修改布尔配置并正确回读。
- 旧表单的异步完成不会关闭新打开的编辑表单；待办按钮在关闭右侧 Tab 后仍可正常点击。

Web 使用独立源码副本构建候选包，避免其他本地任务清理共享 `lib/` 时干扰验收。

## 现有 Web 页面恢复验证

2026-09-10，在用户现有 `127.0.0.1:3080` Chrome 页面观察到
`marivo_datasource_configure` 正在等待，但右侧 Tab 和“待配置”入口均未出现。
通过当前会话的只读 `watch` 查询确认：服务端已有 `awaiting-input` 的新增配置请求，
且浏览器仍在查询该 Session；旧页面记录的插件资源版本在当前 Host 返回 404。

仅刷新浏览器页面后，右侧“数据源”Tab 自动打开并直接显示原请求的新增表单、请求说明、
已有数据源选择器及“保存并测试，成功后继续”按钮。原工具调用保持等待。
本次恢复未修改配置或凭证，未重装插件、重启 Host 或重新发起分析。
该证据验证旧页面加载当前客户端后恢复待办，不代表旧客户端可自动获得新客户端功能。

## 保留的限制

仅继续仍存活的原工具调用，不恢复已取消调用或跨 Host 重启的任务。
连接成功不证明目标表可读，Agent 续接后仍须核验目标表。
配置采用先保存、再测试，测试失败不回滚；更换凭证引用不删除旧的共享凭证。
版本校验和串行写覆盖插件内冲突，不保证与外部编辑器之间的原子并发写。
无法通过公开契约完整读取配置及 `ai_context` 时拒绝保存。

本次未发布、推送、重装或重启现有 DSH 服务；验收启动和停止的均为独立临时实例。
