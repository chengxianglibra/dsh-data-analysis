# Report content

Decide the audience, decision, report type, and explicit user constraints before choosing the
structure. The report must answer the user's question; Starter components never justify adding an
otherwise empty section.

- Separate observed facts, Agent inference, and recommendations. Match causal or confidence
  language to the evidence.
- Give every chart a question to answer and explain the implication instead of restating every
  point. Keep a readable fallback.
- Include only content that changes understanding, action, or auditability. Do not fill ceremonial
  summary, KPI, limitation, or appendix sections.
- Keep machine identities and full lineage out of the main narrative unless the audience needs an
  audit view.
- Follow user-specified brevity, ordering, or delivery constraints over any example.

Common, non-mandatory shapes include:

- decision brief: answer, evidence and drivers, action, material limitations, trace appendix;
- audit: scope and definitions, method and evidence, reconciliation or exceptions, limitations,
  trace appendix;
- diagnosis: question and scope, confirmed observations, candidate explanations, unknowns and
  counterexamples, next checks;
- technical report: goal and constraints, method, validation, results, limitations and
  reproducibility information.

The Checker does not require these headings, their order, or any fixed report schema.
