# 创建分析视图与刷新数据

选择能回答问题的最小分析视图。用趋势图看变化、用对比或贡献图定位差异、用数据视图核对精确值；一张图足够时就交付一张图。用户要求报告时以结论和证据组织页面，要求看板时以指标和对比组织页面。遵循用户指定的输出格式。

分析正确性由文件分析或 Marivo 分析流程负责，本 Skill 负责展示与保存。可直接展示的已有结果或一次明确修改可用 `stage:"save"` 提交；需要持续计算的视图按以下流程增量预览。

## 组件与数据准备

复用符合范围和时效的固定结果及其 `codeRef`。新计算在独立进程读取准确输入并持久化新结果，不依赖前次内存或临时表。

每个数据视图使用独立命名语句；相同结果可共享资源名，不同标签可用同一引用的不同资源名。新结果原样使用 Python 返回的完整 resource；文字和布局无需 Python，Image 不支持 codeRef。

用 `AnalysisFrameView` 保留已有 Frame 的结构，纯文件结果可用 `DatasetView`。已有结果缺少执行脚本时说明来源缺口，直接复用结果。

通过 Python `results[name].metadata` 选择准确列、值和轴；`marivo_report_write` 的结构化 `resultMetadata` 和配置错误提供准入快照的覆盖与候选名。配置修复只改展示，不为取元数据重跑业务计算。首次交付持久结果时读[结果引用](references/capture.md)。组件和图形选择见[视图与布局](references/analysis-ui.md)，OpenUI Lang 参数以生成的[组件签名](references/analysis-catalog.md)为准。

项目分析或持久化使用 `marivo_python(project:"required")`，插件准备绑定 Workspace 根项目，具体失败按回执处理。

## 边分析边更新

1. 确定需要持续计算的分析视图后，尽早调用 `marivo_report_write(stage:"preview")` 展示已知问题和范围。初始 `program` 可以只有标题、范围和待回答的问题，省略 `resourcePatch`；只引用就绪资源，只写已有证据支持的结论。
2. 按实际依赖与资源预算安排新计算，优先复用已有准确结果。任意 Python 和草稿写入当前由 Harness 串行调度，不承诺并发。Frame/DataFrame 在生产调用内持久化，通过 `resultVariables` 导出准确引用；保留完整的 `results[name].resource` 及独立的来源/元数据状态。
3. 结果就绪后及时 preview，不等全部计算；同批相关视图可合并更新。使用上一成功回执的 `ref`，提交新增或替换的完整命名语句，并使组件从 `root` 可达。`resourcePatch.put` 新增或替换资源，`resourcePatch.remove` 删除资源；未提及的保留。候选在完整身份和 patch 到达后才能更新；参数顺序不影响最终正确性。单组件失败保留草稿并处理或说明，其他无依赖计算可继续。
4. 核对请求覆盖、数据与结论一致性及实质限制后，用最新草稿标识调用一次 `stage:"save"`，可同时提交最后一批修改。正式历史只新增一个版本，成功返回 saved `ref`。未完成部分明确说明，不把预览成功当成正式保存。

视图位置由读者管理，PTC 按实际 dispatch 更新。每个 Session 有一个当前 Turn 草稿，串行调用 preview/save，显式指定 stage。回执确认写入状态。草稿在 Turn 结束或 Host 重启时失效。缺上下文或冲突时读[恢复参考](references/recovery.md)，调用见[页面示例](references/examples.md)。

## 刷新已保存视图的数据

用户要求更新已保存视图的数据时，使用 `mode:"refresh-data"` 按[数据刷新](references/data-update.md)执行，不要求用户再声明“保持布局”。保留页面程序、组件、资源名、view/display、正文、标题、语言和标签；auto 换图由工具拒绝，内部几何仍可随行数变化。按实际固定结果显式重算并 preview 同名资源替换，同一新结果可以供多个原有视图使用，最后保存一次。不能为通过校验换图形、删组件或改口径。

明确要求改布局或正文时，才进入页面编辑：读取准确基版本，保留未请求修改的内容，增量 preview 变更后统一保存。若还要新数据，其准备仍使用显式输入和新持久输出。数据刷新不隐含页面编辑。

## 表达与完成

用 `TextContent` 写解释，数据视图呈现可核对的数值和图形，`Stack`、`DashboardGrid`、`Card`、`Tabs` 和 `Accordion` 组织阅读；`TextCallout` 用于说明范围和假设。数据视图已有结果外壳，不为单个视图再加装饰性 Card。已有图片或不支持的图形可用 Image，需要核对原值时配独立数据视图。

草稿尚无结论时展示问题和证据缺口；结论成立后把结论、支持数据和影响解读的范围、分母、缺失项放在一起。比较、归因和覆盖检查见[叙事与证据](references/narrative.md)。

每轮最终视图保存后，用准确 saved ref 提交本轮新的下一步推荐，明确无建议可提交 no-suggestions，推荐不结束 Turn，继续完成其他交付；上一轮曾推荐但未执行不等于已经回答。用户明确不要推荐时，以 `items:[]`、`emptyReason:"declined"` 尊重其要求；无合适推荐不应冒称用户拒绝。

视图保存成功后，最终聊天回复通常只用一两句话给出核心结论和会改变解读的限制，可提示从右侧打开分析视图。用户要求在聊天中提供的内容仍需直接回答。图表、逐项数字、过程和已交付的推荐留在各自入口，聊天无需复述。若只有草稿或保存失败，说明实际交付状态，并在聊天中给出已有证据支持的答案。
