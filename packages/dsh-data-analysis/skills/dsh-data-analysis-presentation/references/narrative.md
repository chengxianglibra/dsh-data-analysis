# 报告与看板叙事

报告和看板仍是同一份有序 blocks 文档。按用户问题选信息密度，不要求固定章节、图数或 KPI 数量。

## 报告

先给已经得到的主要结论，再放最能支撑它的数据和比较。解释时间范围、粒度、单位、缺失与截断；把事实、分析判断和待验证假设分开。结论尚未成立时说明现有证据和缺口，不用图形复杂度替代分析。

正文使用 markdown，关键单值用 metric，变化或比较用 line/bar，需要核对原值时用 table。来源面板提供精确 Artifact 和公开事实；只为当前问题读取必要 Finding，不强制遍历整个 SessionGraph。

## 看板

先列要回答的运营问题，再选已计算的关键指标、趋势或分组比较。对比区间、分母、单位与目标如果未从分析取得，就明确缺失；不要让展示层补造。metric 指向一格已有数据，不自动计算总计、达成率或同比。

用 blocks 顺序表达优先级，适配布局由 reader 决定。这是生成时的数据快照；当前范围、生成时间和实质限制应让读者可见。新的范围或刷新需要新分析和一次新的 present。

## 交付说明

简要回答问题，附 receipt 的打开/下载入口或 headless 精确路径。说明会影响结论的截断、来源 unavailable、近似绘图或未完成验证。present 的结构与来源读取成功不等于统计正确、业务口径正确或 computed 转换已获验证；只报告已取得的证据。
