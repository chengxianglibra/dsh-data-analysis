# 叙事与证据检查

报告、看板及比较型展示在编写 program 前读取本页。按用户问题选信息密度，不要求固定章节、组件数或 KPI 数量；以下检查用于表达已有分析，不代替 Runtime Skill 的分析与质量契约。

## 保持问题与比较范围

逐项对应用户的问题与比较范围：每组比较明确两侧的时间或群体、粒度、单位、方向和比例分母。不同基准分别回答，不能用一个成功比较替代另一个；某分支未取得数据时，在正文说明已回答范围、尚缺证据及其影响。

以 `current - baseline` 表示变化时，列名和正文统一该方向；若另用 `baseline - current` 表示减少量，明确命名。交付前从原值核对差值、比例、全量合计与余项，核对文字中的大小、方向和量级；占比的分母不能在正文中悄然换成另一个比较或筛选后子集。

## 让结论匹配证据

区分观测事实、数值贡献分解、解释与待验证假设。分解能说明哪些项贡献了净变化；原因、角色推断及“排除某原因”的结论需要相应证据，未观察到不能直接当成不存在。两个维度各自的边际分布不能证明它们的联合关系；需要交叉证据才能描述组合群体或共同驱动。

把实质限制落实到对应结论的范围和措辞，不能只在末尾加免责声明后仍作强断言。证据不足时交付已支持的答案和明确的未决问题，不让展示文案补造缺失分析。

## 说明选取与未展示部分

Top N、过滤或预聚合必须说明选取规则、排序方向与覆盖范围。Agent 在捕获前选取的子集，与 `capture_dataset` 因预算截断不同；快照的行数与截断状态只描述捕获时收到的 DataFrame，未截断不证明业务数据全量。

当结论涉及全量归因，保留可核对的全量基准和未展示项的净贡献，校验“展示项净变化 + 其他项净变化 = 全量净变化”。部分减少项之和可能超过全量净减少，因为其他项抵消；不要将局部和称为总差或把它与全量净差的比值当成覆盖率。可改写的[比较示例](examples.md#比较与抵消项)展示原值、净差、减少量和抵消量的关系。

## 报告

先给已经得到的主要结论，再放最能支撑它的数据和比较。结论尚未成立时说明现有证据和缺口，不用布局复杂度替代分析。
会话内展示的宽度有限（约 750px）：首屏最多 5 个指标、单表最多 6 列；更多内容用 `surface:"tab"` 或 Tabs 分组，
不要靠横向滚动塞下宽表。单行多组比较直接省略 program，由 Frame 结构生成一张对比表。

说明文字用 TextContent，关键单值用 metric 视图，需要核对原值时用 table，未确定时用 auto；多组结果可用 Tabs 分组。数据视图展示快照已捕获的来源与范围，不另造来源段落；只为当前问题读取必要 Finding，不强制遍历整个 SessionGraph。

## 看板

先列要回答的运营问题，再选已计算的关键指标、趋势或分组比较。对比区间、分母、单位与目标如果未从分析取得，就明确缺失；不要让展示层补造。metric 指向一格已有数据，不自动计算总计、达成率或同比。

用 program 中的组件顺序与 Stack/Card 布局表达优先级。这是生成时的数据快照；当前范围、生成时间和实质限制应让读者可见。新的范围或刷新需要新分析和一次新的 present。

## 交付说明

将回答问题所需的结论、解释及影响结论的截断、缺失来源或未完成验证放入同一份报告正文。成功交付后最终文字尽量只写一句总结，不再复述正文；展示失败则说明实际状态并基于已有证据回答。present 的结构与快照读取成功不等于统计正确、业务口径正确或捕获前的转换已获验证；只报告已取得的证据。
