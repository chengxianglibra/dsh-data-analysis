# 视图选择与页面布局

## 选择数据来源与刷新契约

适用的 governed 分析优先保留持久化 AnalysisFrame 并使用 AnalysisFrameView；文件或合法外部计算的 DataFrame 使用 DatasetView。每个数据视图使用独立命名语句；多个视图可以共享同一准确固定资源或引用并保留原生产 codeRef，不为不同展示重复计算。派生结果显式读取准确固定输入、保存新输出，代码记录不冒充完整依赖图。

新建可刷新报告时，按已核验的字段尽量显式选择 chart 和 encoding；table 可明确 columns，避免列随数据变化。auto 适合探索草稿或只能由 Frame 结构判定的视图，不承诺刷新后的呈现形态固定。部分 comparison/decomposition 视图也会按结构调整内部布局。保持分析粒度、角色和字段契约，并核对形态；不能通过新增空值、伪造行或改变业务口径维持外观。

刷新已保存报告时锁定原 view/display 和布局。数据不满足旧视图时修复其数据输入或说明阻塞，不改成其他图形。以下视图选择建议用于新建或明确授权的页面编辑。

## Marivo Frame

`AnalysisFrameView("result")` 根据 Frame 的结构选图。单行单组比较适合读本期值与变化；单行多组比较（单一比较、最多 8 个指标）默认每个指标一个头部数字块，依次展示本期、基期、Δ、Δ%，更多指标或多个 alias 时回退为一张“指标 × 本期/基期/Δ/Δ%”对比表。显式 `{chart:"table"}` 始终是这张对比表；多行比较按时间或类别组织。柱图可用于时间轴或普通类别轴（按保存行首次出现顺序等距排布），折线图和面积图要求时间轴。要突出某一组，可以用 `{chart:"comparison", encoding:{value:"输出列名"}}` 引用该组的公开值名。分解图使用 Frame 已有的分解结果。

饼图适合观察型 Frame 的构成比较。快照须完整，只有一个分类轴，类别键唯一。选择一个非广播数值列，值须非空、有限、非负且至少有一个正值。用 `{chart:"pie", encoding:{axis:"轴名", value:"值名"}}` 指定字段，目标唯一时可省略映射。

需要堆叠构成条时，可在同一个 pie 声明中指定 `style:"stacked"`；比例按已展示的完整分类值计算，并标记为计算值。原始数值和点选仍对应保存行，未指定 style 的饼图保持不变。

`display` 的标题、格式和范围必须由报告作者根据已核验口径明确声明：

- `title`、`subtitle` 用于说明图表；`formats:[{value:"已保存值名",format:"percent"|"number"|"currency",decimals:1}]` 只改变主视图显示，不改变原始值、复制或数据详情。百分比按保存比例乘以 100。
- 比较端点确有明确名称时，可用 `comparisonLabels:[{alias:"比较别名",current:"本期名称",baseline:"基期名称"}]`；保存的匿名比较使用 `alias:null`，仅当该 alias 在快照中唯一对应一个比较时可用。名称由作者负责核实，不能从字段名称或数值猜测。
- 时间柱图可用 `highlight:{axis:"轴名",key:[已保存的完整原始键]}` 强调特定期间；键必须逐项匹配快照。横向分类条可用 `rowLimit` 预览前 N 条保存行，完整结果仍在数据入口。
- 表格可用 `recordPreview:{coordinates:["坐标列1","坐标列2"],values:["数值列"],limit:6,label:"组合坐标标题"}` 将坐标按声明顺序连接，数值和点选仍指向原行；完整结果见数据入口。
- 已核实分解的两期 level total 与所选变化属于同一分组和范围时，可用 `decompositionTotals:{current:"本期总量列",baseline:"基期总量列",currentLabel:"本期标题",baselineLabel:"基期标题"}` 展示保存总量。仅在每个总量在保存行中一致且非空时显示；不要自行求和替代缺失总量。

## DataFrame

`DatasetView` 按保存的列 ID 映射字段。表格可用 `{chart:"table", columns:["category", "amount"]}` 选择读者需要核对的列。指标卡使用完整单行结果中的一个标量，支持文本；图表的数值映射仍须符合对应类型约束。折线图、面积图和柱图用 `{axis, values, series?}`，热力图用 `{x, y, value}`。这些图要求完整快照、数值列和唯一坐标组合，按快照中首次出现的顺序展示。趋势图应使用原分析已经按时间排好的数据。

## OpenUI Lang 布局

从 `root` 组合页面，组件按[签名](analysis-catalog.md)接受位置参数。初始草稿可仅含标题、问题与范围文字，不使用未就绪资源。每个数据视图使用独立命名语句，结果就绪后连同 root/父布局 patch 加入草稿；保留其他已完成组件。将结论和必要的范围说明也写成命名语句，便于增量更新。数据视图已有结果卡片，直接放在 Stack 或 TabItem 中；不要只为单个视图添加装饰性 Card。Card 可用于有共同主题的内容。需要并排时为 Stack 指定 row 和 wrap，使卡片在窄屏可以换行。

已有图片或数据视图不支持的图形可用 Image 的资源名引用，给它写出能说明内容的替代文字；读者需要核对原值时配数据视图。数据视图的条件不满足时，选择合适的表格或说明限制，不通过图片或文字掩盖缺失或不完整的数据。
